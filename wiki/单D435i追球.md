# 单 RDK + D435i 追球

本模式只使用 RDK、D435i 和底盘 `/odom`：D435i 发布逐帧 RGB-D 球心，
`catch_controller` 在 `odom` 下估计弹道和球心接触平面落点，`goal_to_cmd_vel` 将当前
`base_link` 下的接球误差转换为 `/vision/cmd_vel`。

## 坐标和标定

坐标采用 REP-103：`base_link` 的 x 向前、y 向左、z 向上；D435 optical 的 x 向右、
y 向下、z 沿光轴向前。相机光轴向上 15°、无额外滚转和偏航时，名义旋转四元数
`[x, y, z, w]` 为：

```yaml
d435_camera_quaternion: [-0.43045933, 0.43045933, -0.56098553, 0.56098553]
```

它满足：相机前方映射到车体 `[cos(15°), 0, sin(15°)]`，相机右方映射到车体右方，
相机下方映射到车体前下方。

当前实测几何尺寸为：

- D435 光心离地 `1.056 m`；
- 击球盘中心在光心前方 `0.591 m`；
- 击球盘面比光心低 `0.500 m`，因此盘面离地 `0.556 m`；
- D435 发布的是排球球心，所以球从上方接触盘面时的球心高度为
  `0.556 + 0.1075 = 0.6635 m`。

对应名义配置为：

```yaml
intercept_plane_z_m: 0.6635
d435_camera_translation: [0.0, 0.0, 1.056]
catcher_point_base: [0.591, 0.0, 0.556]
```

这里暂时把 `base_link` 原点定义为 D435 光心正下方的地面点。如果底盘 `/odom` 的
`base_link` 原点是底盘几何中心或其他位置，必须通过下面的多点手眼标定求出真正的
`d435_camera_translation`；击球盘坐标应始终满足
`catcher_point_base = d435_camera_translation + [0.591, 0, -0.500]`。

## 多点手眼标定

D435 光轴向上 15°，击球盘接触球心相对光轴约向下 48.6°，通常已经超出彩色相机垂直
视场，因此不要只把球放在击球盘上做单点标定。单个点也无法同时确定三维旋转和平移。

固定底盘不动，准备一个能把排球球心固定在已知位置的支架。以真实 `base_link` 原点为
基准，测量至少 6 个可见球心位置 `[x_forward, y_left, z_up]`，位置要覆盖左右、远近和
不同高度，不能排成一条直线。每个位置采集一次：

```bash
rm -f /tmp/d435_handeye_samples.jsonl

ros2 run volleyball_catch_controller capture_d435_calibration_point \
  --ros-args \
  -p base_point:="[0.80, 0.30, 1.30]" \
  -p sample_count:=60 \
  -p output_path:=/tmp/d435_handeye_samples.jsonl
```

移动球到下一个已测位置后重复命令。采集节点只接受可靠 RGB-D，默认对 60 帧做中值和
离群点剔除，并向 JSONL 文件追加一组相机球心/车体球心对应点。全部采集后求解：

```bash
ros2 run volleyball_catch_controller solve_d435_handeye \
  /tmp/d435_handeye_samples.jsonl --max-rmse-m 0.020
```

输出中的 `d435_camera_translation` 和 `d435_camera_quaternion` 直接复制到
`catch_controller_d435_only.yaml`。要求：

- `accepted=true`，RMSE 建议不超过 20 mm；
- 平移 z 应接近 `1.056 m`；
- 四元数方向应接近名义 15°安装值；
- 任一单点误差明显偏大时，删除该点并重新测量，而不是放宽阈值。

确认后才将 `d435_extrinsics_calibrated` 改为 `true`。实车运动前还应检查击球盘中心：

```yaml
catcher_point_base:
  [camera_x + 0.591, camera_y, camera_z - 0.500]
```

YAML 中不能写上述算式，需要填入计算后的三个数值。

## 落点到击球盘精调

手眼外参解决“相机三维点到车体坐标”的几何关系；真实抛球仍可能受深度偏差、空气阻力
参数和盘面安装误差影响。完成低速安全测试后，连续记录至少 10 次球在盘面相对中心的
实际落点，坐标同样使用 x 向前、y 向左。将平均落点偏差直接填入：

```yaml
landing_goal_correction_base: [mean_impact_x, mean_impact_y]
```

例如球平均落在盘中心前方 30 mm、右侧 20 mm，则填写 `[0.030, -0.020]`，控制器会让
击球盘向同一方向补偿。每次只更新平均偏差，重新测试后再迭代，避免用单次抛球修正。

实车运动前必须编辑
`ros2_ws/src/volleyball_catch_controller/config/catch_controller_d435_only.yaml`：

1. 填入多点手眼标定得到的 D435 外参。
2. 按 D435 与击球盘的相对尺寸计算 `catcher_point_base`。
3. 核对接触球心平面 `intercept_plane_z_m=0.6635`。
4. 核对外参和方向后，将 `d435_extrinsics_calibrated` 改为 `true`。

默认保持 `false`，此时仍发布滤波和预测诊断，但不会产生有效底盘目标，避免用零平移假装
完成外参标定。

`intercept_plane_z_m=0.6635` 表示预测排球球心到达击球盘接触高度时的位置。若 500 mm
测量的是盘架中心而不是实际盘面，必须重新测量盘面高度后再计算。

## 构建和启动

```bash
source /opt/ros/humble/setup.bash
cd ~/desktop/RDK-S100p-BPU-yolo/ros2_ws
colcon build --symlink-install
source install/setup.bash

ros2 run volleyball_catch_controller check_chassis_odom \
  --ros-args -p topic:=/odom
```

确认里程计为 `frame_id=odom`、`child_frame_id=base_link`，采集时间属于 RDK 系统时间域，
频率至少 20 Hz。然后启动追球控制：

```bash
ros2 launch volleyball_catch_controller d435_only_chase.launch.py \
  odom_topic:=/odom cmd_vel_topic:=/vision/cmd_vel
```

另一个终端启动 D435i 推理：

```bash
cd ~/desktop/RDK-S100p-BPU-yolo/yolov8/build
./yolov8_usb_camera \
  --config=../config/yolo26_d435i_848x480_60fps.yaml
```

D435 配置默认使用 848x480@60 FPS、5000 us 固定曝光、6 m 深度上限、0.25 检测阈值，
并关闭视觉进程内部的轨迹预测，RDK 控制节点是唯一弹道和控制决策者。现场光照变化较大时，
先重新调曝光和增益，再调整检测阈值。

## 首次测试顺序

先将输出重映射到测试话题，底盘不要进入视觉控制档：

```bash
ros2 launch volleyball_catch_controller d435_only_chase.launch.py \
  odom_topic:=/odom cmd_vel_topic:=/vision/cmd_vel_test

ros2 topic echo /catch/state
ros2 topic echo /auto/goal_pose
ros2 topic echo /vision/cmd_vel_test
ros2 topic echo /diagnostics/transport
```

检查要点：

- 连续可靠 RGB-D 后状态进入 `NEAR_D435`，`active_source=SOURCE_D435`；
- `/auto/goal_pose` 的 x 向前、y 向左，人工移动球时方向正确；
- D435 或 `/odom` 停止后，速度在一个控制周期内归零；
- 速度模长不超过 0.40 m/s，加速度模长不超过 0.80 m/s²；
- 接球点进入 0.10 m 停止半径后输出零速。

完成架空轮测试和低速地面测试后，再恢复 `/vision/cmd_vel`。现有底盘仅在 RC 左拨杆下档
转发视觉速度，并有约 0.3 s 输入超时保护；本节点自身仍以 50 Hz 主动发布零速或有效速度。
