# 远近场接球系统设计

最后确认：2026-07-13

## 节点边界

```text
NX stereo_vision ── /nx/ball/observation ─┐
                                          │
RDK d435_vision ── /d435/ball/observation ├─► RDK catch_controller
                                          │       ├─ /auto/goal_pose
底盘 ───────────── /odom ─────────────────┤       ├─ /auto/goal_valid
击球机构 ───────── /catch/event ──────────┘       ├─ /ball/landing
                                                  └─ /catch/state
```

- NX：双目检测和同帧原始三维观测，只发布数据，不做控制轨迹滤波。
- D435i：始终后台检测和测距，只发布逐帧观测。
- `catch_controller`：唯一控制节点，负责坐标变换、状态机、近场滤波、落点预测、
  复位和控制发布。
- NX、D435i 不得发布 `/auto/goal_pose`。

## 状态机

| 状态 | 控制来源 | 行为 |
|---|---|---|
| `IDLE` | 无 | 等待 NX 新的有效原始观测，由RDK生成 `catch_id`，`goal_valid=false` |
| `FAR_NX` | RDK基于NX观测预测的落点 | 底盘追踪远场落点，D435i 仅后台缓存 |
| `WAIT_D435` | RDK远场落点 | 继续更新NX目标，同时积累并校验D435i近场候选 |
| `NEAR_D435` | D435i 落点 | 本周期不可逆切换，由 D435i 近场轨迹控制 |

状态转移：

```text
IDLE --有效NX新周期--> FAR_NX
FAR_NX --接球机构到达NX落点半径--> WAIT_D435
WAIT_D435 --D435连续RGB-D且与NX预测一致--> NEAR_D435
任意活动状态 --任意复位条件--> IDLE
```

到达判断使用接球机构在 `odom` 中的位置，而不是默认使用车体中心：

```text
p_catcher_odom = T_odom_base(now) * p_catcher_base
arrived = distance_xy(p_catcher_odom, nx_landing_odom) <= arrival_radius_m
```

`arrived` 一旦成立就在当前 `catch_id` 内锁存。D435i 进入候选交接的前提为：

```text
base_arrived_latched && d435_detection_valid
```

`WAIT_D435` 期间 NX 继续更新远场滤波和控制目标，D435i 独立积累近场候选。正式进入
`NEAR_D435` 必须同时满足：连续检测确认、连续有效 RGB-D、近场滤波和落点稳定、D435
三维位置与 NX 同时刻预测通过 Mahalanobis 门控、两个来源预测落点差小于配置阈值。
只有完成这组同目标关联后切换才不可逆；单帧 bbox 检测不能夺取控制。

## 坐标和运动补偿

控制和落点稳定判断统一在连续的 `odom` 坐标系中完成：

```text
p_ball_odom(t_capture)
  = T_odom_base(t_capture) * T_base_camera * p_ball_camera(t_capture)
```

两个固定外参分别为 `T_base_nx_camera` 和 `T_base_d435_camera`。必须配置完整平移和
四元数；未配置或非法时禁止发布有效控制目标。

控制节点保存至少 3 秒 `/odom` 环形历史。对采集时刻插值三维位置和完整四元数姿态；
最大插值间隙 50 ms，最多外推 20 ms。不得用网络接收时刻的底盘位姿补偿相机坐标。

当前阶段`/odom`直接来自舵轮底盘标准`nav_msgs/Odometry`，不使用本仓库自建码盘算法，
也暂不融合D435i IMU。输入必须满足`frame_id=odom`、`child_frame_id=base_link`、采集时间戳
与RDK系统同域，推荐50–100 Hz。控制器拒绝零时间戳、超过50 ms的旧样本、未来时间、
时间倒退和错误frame；后续可在保持同一接口的情况下替换为融合odom。

NX 落点转换成 `landing_odom` 后是世界固定点。发送到底盘前再转换为当前
`base_link` 坐标：

```text
goal_base(now) = inverse(T_odom_base(now)) * landing_odom
```

## 远场与近场处理

远场由 RDK 将 NX 原始双目观测按采集时间转换到 `odom`，再运行统一轨迹滤波和
弹道预测。NX 不需要订阅底盘里程计，也不向 RDK 发送速度或落点。

近场由控制节点使用 D435i 原始观测运行轨迹估计：

```text
RGB-D有效 → RGB-D更新
短时深度失效 → Kalman预测
持续失效但bbox仍有效 → 保持最后预测，暂不使用无三维坐标的单目观测更新
bbox也失效 → 有限时间保持，随后按球丢失复位
```

近场目标仍是预测落点，不直接追逐球当前投影位置。

控制节点内部维护两个互相独立的 Student-t 鲁棒 6D EKF：`far_tracker` 只接收按采集
时刻转换到 `odom` 的 NX 观测，`near_tracker` 只接收按采集时刻转换到 `odom` 的
D435i RGB-D 观测。滤波预测模型、排球质量/半径、空气阻力系数、过程噪声和 RK4 步长
与 NX 当前 Student-t EKF 主路径一致；在 RDK 中重力固定为 `odom` 的 `-Z`，地面为
`ground_z_m`。每次通过速度、Student-t 权重、剩余时间和连续稳定门控后，发布滤波
位置、速度、预测弹道和落点。底盘运动不会被误认为球速，因为相机观测会先使用历史
`/odom` 完成运动补偿。视觉订阅回调只缓存最新消息，坐标变换、滤波、交接和控制统一
在 100 Hz 控制循环执行。

NX 的 ROS 输出位于 `HybridDepthEstimator` 之后：先完成单目/双目混合深度和近似 9D
深度跟踪，再把当前帧的 `raw_x/raw_y/raw_z` 混合观测发送给 RDK。RDK 不直接继承 NX
的 9D 状态，而是使用该观测、测量协方差和采集时刻 `/odom` 独立估计世界坐标弹道。
NX 远场与 D435i 近场分别维护轨迹，不要求两台相机帧级同步。

## 复位

以下任意条件成立即复位：

1. 球连续丢失超过配置时间；
2. 当前绝对预计落地时刻已经到达并超过宽限时间；
3. 收到当前 `catch_id` 的已击球回球事件。

同一周期同时出现多个条件时，记录优先级为：`RETURNED_EVENT`、
`IMPACT_TIME_REACHED`、`BALL_LOST_TIMEOUT`。

- `FAR_NX/WAIT_D435` 的球丢失依据 NX 消息超时，建议 0.30 s。
- `NEAR_D435`依据通过时间门控的D435i RGB-D更新超时，建议0.80 s；只有bbox而没有可靠
  深度时不得继续维持近场控制。
- 使用绝对 `impact_time`，建议 `impact_grace_s=0.15`。
- 保存周期硬截止时间，防止异常预测不断向后推迟复位。

复位必须原子完成：清除周期 ID、轨迹、落点、到达锁存和门控计数，立即发布
`/auto/goal_valid=false`，停止使用旧目标。

## 建议初始配置

```yaml
catch_controller:
  world_frame: odom
  base_frame: base_link
  handover:
    arrival_radius_m: 0.80
    d435_confirm_frames: 3
    d435_min_confidence: 0.30
    d435_max_rgb_depth_delta_ns: 2000000
    d435_max_timestamp_uncertainty_s: 0.002
    irreversible: true
  reset:
    nx_lost_timeout_s: 0.30
    d435_lost_timeout_s: 0.80
    impact_grace_s: 0.15
    max_cycle_extension_s: 1.0
  odometry:
    history_s: 3.0
    timeout_s: 0.10
    max_interpolation_gap_s: 0.05
    max_extrapolation_s: 0.02
  extrinsics:
    nx_calibrated: false
    d435_calibrated: false
```
